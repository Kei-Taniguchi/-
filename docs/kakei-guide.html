家計Webアプリ 操作・復旧ガイド

このページは、これまで一緒に構築してきた家計Webアプリについて、普段の起動方法・Excelデータ同期・データ更新・入力ルール・502エラー対応・よく聞いていた操作を1か所にまとめたものです。

現在の構成： 家計.xlsm → GitHub Actions → data/kakei.json → Webアプリ

1. まず覚える3つの場所

場所役割
家計.xlsm元データ。月ごとの収入・支出、分割・リボなどを入力するExcel。
GitHubリポジトリExcelを解析するプログラム、Webアプリ本体、Webアプリ用データを管理する場所。
CodespacesWebアプリを実際にブラウザで確認するときに使う開発環境。

2. CodespacesでWebアプリを表示する手順

  1. Codespacesを開く。
  2. ターミナルでリポジトリのフォルダにいることを確認する。
  3. GitHub側の最新変更を取得する。
git pull origin main

その後、Webサーバーを起動します。

python3 -m http.server 8000

Serving HTTP on 0.0.0.0 port 8000 と表示されたら起動成功です。

  1. Codespaces下部のPORTSを開く。
  2. 8000の行からOpen in Browserを開く。
ポイント： ターミナルでWebサーバーを起動したままにしてください。終了するとブラウザからアクセスできなくなります。

3. Excel「家計.xlsm」と家計簿・支払い計画を同期する方法

同期の基本： Excelの最新ファイルをGitHubリポジトリの家計.xlsmに反映すると、GitHub ActionsがExcelを解析し、data/kakei.jsonを更新します。WebアプリはこのJSONを読み込んで家計簿・支払い計画を表示します。

通常の更新手順

  1. Excelの「家計.xlsm」を更新・保存する。
    月別シート、支払い計画、分割分シートなど、反映したい内容をExcel側で変更します。
  2. 最新の「家計.xlsm」をGitHubリポジトリに反映する。
    リポジトリ内の家計.xlsmを最新ファイルに置き換え、GitHubへコミット・Pushします。
  3. GitHub Actionsの完了を待つ。
    Actionsがscripts/import_budget.pyでExcelを解析し、data/kakei.jsonを生成・更新します。
  4. Codespacesで最新データを取得する。
git pull origin main
  1. Webアプリを再読み込みする。
    必要に応じてCtrl + F5で強制再読み込みします。

同期されるデータの流れ

段階データ役割
①家計.xlsmExcelで管理している元データ。
②scripts/import_budget.pyExcelの月別収支・支払い計画・分割・リボ等を読み取ってWeb用データへ変換。
③data/kakei.jsonWebアプリが読み込む最新データ。
④app.jsJSONを画面に表示。家計簿、支払い計画、分割・リボ残金管理、ガントチャート等を更新。
重要： GitHub Actionsが直接OneDriveのC:\Users\...にあるExcelを監視・同期する仕組みではありません。Actionsが処理するのはGitHubリポジトリに保存された「家計.xlsm」です。したがって、ExcelをOneDrive上で変更しただけではWebアプリには反映されません。

「分割分」シートを変更した場合

分割分シートを変更した場合も、同じ同期手順です。最新の家計.xlsmをGitHubへ反映 → GitHub Actions完了 → Codespacesでgit pull → ブラウザ再読み込みの順で操作してください。

正常に反映されると、Webアプリの「分割・リボ残金管理」と「分割・リボ残金のガントチャート」にExcel側の更新内容が反映されます。

同期できたか確認するポイント

  • GitHub上の家計.xlsmの更新日時・コミットが最新になっている。
  • GitHub ActionsのExcel解析処理がSuccessになっている。
  • data/kakei.jsonの生成日時が更新されている。
  • Codespacesでgit pull origin main後、Webアプリを再読み込みしている。
  • 分割・リボの区分や残金が最新のExcel内容になっている。

4. 今回の502エラーの原因と直し方

今回の502は、8000番ポートでWebサーバーが起動していなかったことが原因でした。

ブラウザが502を表示し、ターミナルで次の結果になった場合：

curl: (7) Failed to connect to localhost port 8000 after 0 ms: Couldn't connect to server

次を実行します。

python3 -m http.server 8000

もし既に同じサーバーが残っている可能性がある場合は、次でも復旧できます。

pkill -f "http.server 8000" || true
python3 -m http.server 8000

確認コマンド

curl http://localhost:8000

HTMLが返ってくれば、サーバーは正常です。

5. 現在の入力ルール

月の収入

各月シートのB列に記載されている数値を合計します。

ただし、既存のExcel構成ではB7が残高セルのため、収入の合計からは除外しています。

例：B3＝100,000円、B4＝50,000円、B5＝20,000円なら、月収は170,000円です。

月の支出

月シートの支出欄について、明細が入力されている金額を集計します。Webアプリ側ではExcel由来の支出に、Web画面から追加した手入力支出も加算します。

Web画面からの手入力

  • 日付：必須
  • 収入／支出：選択
  • カテゴリー：選択
  • 金額：1円以上の整数
  • 支払方法：選択
  • クレジットカードを選んだ場合：カード選択が必要
  • 分割払いを選んだ場合：分割回数が必要
  • 収入は通常払いのみ

6. アプリの画面構成

  • 月別の収入・支出・残高：画面上部に表示。
  • 入力フォーム：収入・支出を選択し、ルールに沿って入力可能。
  • 自動入力チェック：必須項目や支払方法に応じた条件を自動確認。
  • 手入力データ：ブラウザのlocalStorageに保存。
  • カード・サービス予定：支払予定を確認可能。
  • 分割・リボ残金管理：借金先・区分・月額・Excel残金・現在残金・終了予定を確認可能。
  • 分割・リボ残金のガントチャート：分割とリボを区別して返済期間を確認可能。
  • 月別生活費の円グラフ：生活費のカテゴリー別構成を確認可能。
  • 借金先・区分・金額の円グラフ：分割・リボの金額を借金先と区分ごとに確認可能。
  • カード情報：カードの引落・締め日情報を画面下部に配置。

7. これまで何度も確認した操作

「変更を反映したい」

git pull origin main

その後、ブラウザを再読み込みします。

「502になった」

python3 -m http.server 8000

起動できたらPORTS → 8000 → Open in Browser。

「localhost:8000につながらない」

curl http://localhost:8000

接続できなければWebサーバーを起動します。

「GitHubの変更がCodespacesに来ない」

git pull origin main

「Excelを変更したのに画面に反映されない」

まず、最新の家計.xlsmがGitHubリポジトリに反映されているかを確認します。次にGitHub Actionsの処理完了を確認し、data/kakei.jsonが更新された後にCodespacesでgit pull origin mainを実行し、ブラウザを再読み込みします。

「OneDriveのExcelを変更したのに反映されない」

OneDrive上の変更だけでは反映されません。最新の家計.xlsmをGitHubリポジトリ側の家計.xlsmに反映してPushする必要があります。

8. 困ったときの確認順

  1. 502？ → python3 -m http.server 8000
  2. ページは開くが古い？ → git pull origin main → ブラウザ再読み込み
  3. Excelの数字が違う？ → B列の入力内容とB7（残高セル）を確認
  4. Excelの更新が反映されない？ → GitHubの家計.xlsmが最新か確認
  5. データ更新されない？ → GitHub Actionsの完了とdata/kakei.jsonの更新を確認
  6. Codespacesが古い？ → git pull origin mainを実行
  7. 入力できない？ → 入力ルール上の必須項目・金額・カード・分割回数を確認

9. 最短復旧コマンド

Webアプリが見えなくなったときは、まずこれだけ覚えておけば大丈夫です。

git pull origin main
python3 -m http.server 8000

その後、PORTSの8000を開きます。
